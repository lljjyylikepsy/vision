OpenCV 学习笔记
=============================================================================

一、常用函数速记
  Mat               声明一个图像（二维像素矩阵容器，自动管理内存）
  imread("地址")     输入图像
  imshow("窗口", 图) 展示窗口
  cvtColor(输入, 输出, 颜色空间)  转换颜色空间
  waitKey()         0 为一直等待按键，具体数值表示等待的毫秒数
  imwrite("地址", 图) 保存图片

  ---- 补充：函数的参数与返回值细节 ----
  imread("路径", flags)
     flags 常用：
       cv::IMREAD_COLOR      默认，读成 3 通道 BGR（丢掉透明通道）
       cv::IMREAD_GRAYSCALE  直接读成单通道灰度图
       cv::IMREAD_UNCHANGED  保留原样（含 alpha，可能是 4 通道）
     读失败返回空 Mat，必须用 img.empty() 判断。
  imwrite("路径", img)
     返回 bool：成功 true，失败 false（不抛异常）。
     扩展名决定保存格式（.png 无损 / .jpg 有损）。
  namedWindow("名", flags)
     WINDOW_AUTOSIZE（默认，窗口随图大小，不能拉伸）
     WINDOW_NORMAL（可以手动拉伸）
  destroyWindow("名") 关一个窗口；destroyAllWindows() 关全部。
  clone() / copyTo()
     都是深拷贝，得到独立像素的一份图。
     clone 直接复制；copyTo 可以带掩膜只复制一部分。
  Mat 常用成员：
     rows, cols   行数(高)、列数(宽)
     channels()   通道数（灰度 1，彩色 3）
     type()       类型编码（如 CV_8UC3）
     depth()      数据类型（如 CV_8U）
     empty()      是否为空
     total()      像素总数 = rows * cols
  at<T>(y, x)
     灰度图：img.at<uchar>(y, x)
     彩色图：img.at<cv::Vec3b>(y, x)   // Vec3b = 3 个 uchar = (B,G,R)
  Mat 常见类型：
     CV_8UC1  单通道 8 位（灰度图、掩膜）
     CV_8UC3  三通道 8 位（BGR 彩色图）
     CV_32FC1 单通道 32 位浮点（matchTemplate 的相似度结果）

二、OpenCV 中的 HSV 颜色表
  OpenCV 的 H 范围是 0~179，S 和 V 范围都是 0~255。
  识别颜色时通常把 S 和 V 设为 50~255 或 100~255，用来排除白色、黑色和太暗的像素。
    红色：  H 0~10 和 H 170~179（红色跨色相环两端，需要两个区间合并）
    橙色：  H 11~25
    黄色：  H 26~34
    绿色：  H 35~85
    青色：  H 86~99
    蓝色：  H 100~124
    紫色：  H 125~155
    粉色：  H 156~169

  ---- 补充：颜色表怎么用、怎么校准 ----
  1. 表的用途
     表里只是“大致 H 范围”，实际要配合 S/V 上下界一起用：
        lower = Scalar(H低, 50, 50);
        upper = Scalar(H高, 255, 255);
  2. 要留容差
     光照、白平衡、摄像头差异会让 H 偏移几点，
     实际阈值常比表里上下各放宽 3~5（绿色 35~85 可用 32~88）。
  3. 怎么实测某个像素的 HSV（校准用）
        cv::Mat hsv;
        cv::cvtColor(img, hsv, cv::COLOR_BGR2HSV);
        cv::Vec3b p = hsv.at<cv::Vec3b>(y, x);
        std::cout << (int)p[0] << "," << (int)p[1] << "," << (int)p[2];
     把鼠标/笔尖指到目标上，读出的 H/S/V 就是该目标的实际值。
  4. 红色为什么要两段
     色相环首尾相接，红跨 0 点，所以要 0~10 和 170~179 两段合并。
  5. 常见误判与对策
     白色/灰色被当成彩色 -> S 太低 -> 提高 S 下界
     阴影被当成目标     -> V 太低 -> 提高 V 下界
     过曝区域变白       -> S 掉到很低，颜色信息丢失，无法识别（只能控曝光）

三、第一次接触 OpenCV 时容易忽略的地方
  1. 图像变量是 cv::Mat。Mat b = a; 只是浅拷贝，a 和 b 共用同一份像素数据；
     如果真的要复制一份独立图像，用 a.clone() 或 a.copyTo(b)。
  2. imread 读入的图像默认是 BGR 顺序，不是 RGB。
     所以 Scalar(0, 0, 255) 在 BGR 图像中表示红色，第三个数值才是红色通道。
  3. cvtColor 转到 HSV 后，H 是 0~179，而不是常见的 0~360。
     这是 OpenCV 和一般颜色教程最不一样的地方，写阈值时不要超过 179。
  4. Scalar 是多个数值组成的小容器，常用来表示颜色或阈值。
     BGR 图像中写作 Scalar(b, g, r)，HSV 图像中写作 Scalar(h, s, v)。
  5. imshow 只是显示窗口，必须配合 waitKey 才会刷新并等待按键。
     waitKey(0) 表示一直等待按键；waitKey(30) 表示等待 30 毫秒，常用于视频循环。
  6. inRange 是闭区间判断，三个通道都满足 lower <= 像素 <= upper 时才算目标。
     返回的 mask 是一张单通道黑白图，白色 255 表示目标，黑色 0 表示非目标。
  7. findContours 是在“黑底白目标”的掩膜上寻找白色连通区域。
     contours 的类型是 std::vector<std::vector<cv::Point>>。
     某些 OpenCV 版本可能修改传入的掩膜，稳妥起见可以传 mask.clone()。
  8. contourArea 返回轮廓面积，常用于过滤太小的噪声区域。
     boundingRect 返回轴对齐矩形 Rect，字段是 x、y、width、height。
  9. 常用的小结构体：
       cv::Point(x, y)        表示坐标点
       cv::Size(w, h)         表示宽度和高度
       cv::Rect(x, y, w, h)   表示矩形区域
       cv::Scalar(v1, v2, v3) 表示多个数值，如颜色或阈值
  10. imread 读取失败时会返回空的 Mat，可以用 src.empty() 判断。
      路径写错或文件不存在时程序不会自动报错，要养成检查 empty() 的习惯。
  11. cv::Mat 中 rows 表示行数（图像高度），cols 表示列数（图像宽度）。
      用 mat.at<cv::Vec3b>(y, x) 访问某个像素时，先写 y，再写 x。
  12. cv::destroyAllWindows() 用来关闭所有 OpenCV 窗口，通常放在 waitKey 之后。
  13. 若使用 using namespace cv; 可省略 cv:: 前缀；
      但项目变大、多个库可能有重名时，建议保留 cv:: 前缀避免冲突。
  14. findContours 里 hierarchy 的类型是 std::vector<cv::Vec4i>，
      Vec4i 是 4 个 int 组成的向量，用来保存轮廓的父子层级关系；
      只做简单颜色识别时，可以先不深入理解它。
  15. 灰度图是“单通道”，彩色图是“三通道”。两者不能直接拼在一起。
      灰度图要和彩色图横向拼接（hconcat）、纵向拼接（vconcat），
      或叠加彩色标注（画框、写字）时，必须先把灰度转成三通道：
          cv::cvtColor(gray, gray3, cv::COLOR_GRAY2BGR);   // gray3 是 3 通道
      注意：
        - COLOR_GRAY2BGR 只是把 1 个通道复制成 3 个，图像看起来还是灰的；
        - 如果只是 imshow 单独显示灰度图，不需要转，单通道可以直接显示；
        - 拼接要求“尺寸相同 + 通道数相同 + 数据类型相同”，否则报错。

  ---- 补充：Mat 内存、ROI、越界、窗口 ----
  1. Mat 是引用计数（浅拷贝不复制像素）
        Mat b = a;          // b 与 a 指向同一份像素，计数 +1
        Mat b = a.clone();  // 真正复制，互不影响
     所以函数参数常用 const Mat& 来避免复制。
  2. ROI（感兴趣区域）是“视图”，不是拷贝
        cv::Mat roi = img(cv::Rect(x, y, w, h));
        roi.setTo(cv::Scalar(0, 0, 0));   // 原图对应区域也会变黑
     想要独立就 roi.clone()。
  3. 坐标对应关系
     图像坐标 (x, y) 中 x 是列(col)、y 是行(row)；
     at<Vec3b>(y, x) 先写 y 再写 x，和数学里的 (x,y) 相反，极易写错。
  4. 越界访问
     at<> 默认不做边界检查，越界会读到脏数据或崩溃；循环边界用 rows/cols。
  5. CV_8U 会溢出回绕
     超出 0~255 的加减会 mod 256；需要安全饱和用 cv::saturate_cast<uchar>()。
  6. 窗口
     同名窗口再次 imshow 会复用；有多个窗口时要多次 waitKey 才能都刷新。
  7. imshow 前必须保证 Mat 非空
     空图 imshow 会触发断言 size.width>0 && size.height>0 失败并崩溃。

四、视频 / 摄像头速记
  cv::VideoCapture cap(path)：用路径打开视频（或摄像头）。
  cap.isOpened()：返回 bool，是否成功打开。
  cap.get(cv::CAP_PROP_FRAME_WIDTH) / CAP_PROP_FRAME_HEIGHT：取视频的宽、高。
  cap >> frame：从视频里取下一帧（每次调用前进一帧），读完或断开时 frame 为空。

  ---- 补充：VideoCapture 的属性、设置与释放 ----
  1. 两种打开方式
        cv::VideoCapture cap(0);          // 整数 = 摄像头索引
        cv::VideoCapture cap("a.mp4");    // 字符串 = 文件路径
     字符串 "0" 会被当成文件名，打不开。
  2. 常用属性 get()
        CAP_PROP_FPS          帧率
        CAP_PROP_FRAME_COUNT  总帧数（摄像头通常 0 或 -1）
        CAP_PROP_FRAME_WIDTH  宽
        CAP_PROP_FRAME_HEIGHT 高
        CAP_PROP_POS_MSEC     当前帧时间戳（毫秒）
        CAP_PROP_POS_FRAMES   当前帧号
  3. 设置参数 set()
        cap.set(cv::CAP_PROP_FRAME_WIDTH, 1280);
        cap.set(cv::CAP_PROP_FRAME_HEIGHT, 720);
     不是所有摄像头都支持，设置后要用 get 确认实际生效值。
  4. 读帧
        cap >> frame;   等价于  cap.read(frame);
     读完或断开时 frame 为空，用 frame.empty() 退出循环。
  5. 释放
        cap.release();
     用完释放，避免设备被占用（否则下次打开报 device busy）。
  6. 摄像头 fps 常取到 0
     建 VideoWriter 时要给默认值（如 25），否则 open 失败。
  7. 循环里必须有 waitKey
     否则窗口不刷新，看起来像卡死。

五、VideoWriter 与 writer.open 详解（保存视频）
  ---------------------------------------------------------------------------
  1. 作用
     VideoWriter 用来把“一帧一帧的图像”写成视频文件，是 imwrite 的视频版。
     视频没有“单张图”的概念，必须由程序逐帧喂进去：writer.write(frame)。

  2. 代码结构（两段式）
     第 1 步：定义空的 writer
         cv::VideoWriter writer;
     第 2 步：打开它，指定输出参数
         cv::Size sz( width, height );
         writer.open("result_video.avi",
                     cv::VideoWriter::fourcc('M', 'J', 'P', 'G'),
                     fps, sz);
     之后循环里：
         if (writer.isOpened()) writer.write(frame);   // 每帧写入
     循环结束后：
         if (writer.isOpened()) writer.release();      // 收尾，确保写盘

  3. writer.open 的四个参数（顺序不能错）
     open( filename, fourcc, fps, frameSize )
       filename : 输出文件名（如 result_video.avi）。相对路径即可，别写死绝对路径。
       fourcc   : 视频编码格式，用 4 个字符组成。常用：
                    'M','J','P','G'  -> MJPG，兼容好、体积较大（推荐新手）
                    'X','V','I','D'  -> XVID
                    'H','2','6','4'  -> H264（部分环境缺编码器会失败）
       fps      : 输出帧率（每秒帧数）。一般直接取输入视频的 fps。
       frameSize: 输出分辨率，类型 cv::Size(width, height)。
                  必须和 write() 喂进去的帧尺寸一致，否则写入无效或报错。

  4. fourcc 为什么写成 4 个字母
     FourCC = "Four Character Code"，用 4 个字符代表一种编码。
     OpenCV 里用 cv::VideoWriter::fourcc('M','J','P','G') 把 4 个字符打包成一个整数。
     写错字母或系统没有对应编码器，open 会失败（isOpened() 返回 false）。

  5. 为什么要先判断 fps / 尺寸再 open
     摄像头或某些源的 fps、宽、高可能取到 0 或负数，直接 open 会失败。
     所以加条件：
         if (fps > 0 && sz.width > 0 && sz.height > 0) writer.open(...);
     这样参数非法时就跳过，不会出错。

  6. 为什么 open 之后要 isOpened 再 write
     open 可能因为编码器缺失、路径不可写而失败。
     每帧写之前判断 if (writer.isOpened())，避免对未打开的 writer 写入导致崩溃。

  7. release 很重要
     VideoWriter 需要 release()（或析构）才会把视频文件的索引写完整。
     不 release 直接结束，生成的视频可能无法播放。放在循环之后调用。

  8. 常见坑
     - 尺寸不匹配：write 的帧尺寸和 open 时给的 frameSize 不一致 -> 视频损坏或写不进。
     - 忘记 release：文件末尾损坏，播放器打不开。
     - 编码器缺失：H264 常常没装，换 MJPG 一般能用。
     - 帧率给 0：视频时长计算异常，务必给正数（摄像头源建议设默认值如 25）。
     - 彩色/灰度不一致：open 默认写彩色；若喂灰度图，最好用 open(..., isColor=false)。


  ---- 补充：VideoWriter 的其它细节 ----
  1. isColor 参数
        writer.open(name, fourcc, fps, size, isColor);
     默认 true（彩色）。要写灰度帧就传 false，否则颜色会错。
  2. 扩展名决定“容器”，fourcc 决定“编码”
        .avi / .mp4 / .mkv 只是容器；编码看 fourcc。
        avi + MJPG 最稳；mp4 可用 fourcc('m','p','4','v')。
  3. 尺寸必须一致
     open 时的 frameSize 必须等于 write() 喂进去的帧尺寸，
     不一致会写入失败或生成损坏视频。
  4. 输出 fps 只影响播放时长
     它与实际写入快慢无关。
  5. open 失败要判断
        if (!writer.isOpened()) { 报错并跳过写入 }
  6. 文件大小
     由 分辨率 x 帧率 x 时长 x 编码压缩率 决定，MJPG 体积偏大。

六、struct Params 详解（把预处理参数集中管理）
  ---------------------------------------------------------------------------
  1. 长什么样（task3）
       struct Params {
           int    thresh    = 127;    // 二值化阈值（可配置）
           int    morphSize = 5;      // 形态学核大小
           double minArea   = 500.0;  // 轮廓最小面积，用于过滤小噪声
       };

  2. 它是什么
     把整个预处理“会用到的可调旋钮”打包成一个小结构体。
        thresh    -> cv::threshold(gray, binary, p.thresh, ...)
        morphSize -> getStructuringElement(..., Size(p.morphSize, p.morphSize))
        minArea   -> if (contourArea(c) >= p.minArea) 过滤噪声

  3. 默认成员初始值（C++11 起）
     “= 127” 表示不指定时用这个默认值：
        Params p;   // p.thresh=127, p.morphSize=5, p.minArea=500.0

  4. 怎么改
        Params p;
        if (argc >= 3) p.thresh = std::stoi(argv[2]);  // 命令行覆盖默认值
     这样“默认能用 + 命令行临时改”，正好满足“阈值可配置”。

  5. 怎么传
        cv::Mat makeMask(const cv::Mat& src, const Params& p) { ... }
     const Params& ：引用传递，不复制整个结构体（省开销），const 表示函数内不改它。

  6. 为什么要用它（对比）
     散着写：cv::threshold(gray, binary, 127, ...) 里 127 写死、散落各处，
             想改要满文件找，而且等于“写死参数”，不符合考核要求。
     用 Params：所有可调参数集中一处，函数间只传一个 p，入口改一次即可；
             现场评委让你改阈值，改一处就能生效。

  7. 一句话
     Params = 把要调的旋钮集中放进一个小盒子：默认值保证能用，
     命令行能覆盖，函数间传递只传这一个盒子。

  8. 延伸：struct 和 class
     C++ 里 struct 和 class 几乎一样，区别只在于：
       struct 默认成员是 public，class 默认是 private。
     只用来“装数据 + 少量逻辑”时，习惯用 struct。


  ---- 补充：参数管理的其它做法 ----
  1. 为什么不用全局变量
     全局变量任何函数都能改，出问题难查；Params 作为参数显式传递，
     谁读谁写一目了然。
  2. 传值 vs 传引用
        void f(Params p);          // 复制一份，函数内改了不影响外面
        void f(const Params& p);   // 不复制、只读（推荐）
  3. 默认成员初始值的限制
     带默认初始值的结构体仍可用 {} 聚合初始化；
     但成员顺序一改，聚合初始化容易错位，建议用对象赋值。
  4. 可调参数 vs 固定常量
     要现场调动的放 Params；算法固定的常量（如 0.02 的 epsilon）留在函数里。

七、二值化的作用（threshold）
  ---------------------------------------------------------------------------
  1. 是什么
     把灰度图（0~255 很多级）变成只有两种值的黑白图：
         像素灰度 > 阈值  ->  255（白，前景）
         像素灰度 <= 阈值 ->  0  （黑，背景）
     代码：cv::threshold(grey, binary, 127, 255, cv::THRESH_BINARY);

  2. 为什么这么做
     (1) 把“连续的问题”变成“是/否的问题”：灰度有 256 种值太复杂，
         二值化后只剩两种——这个像素属于目标吗？
     (2) 分割：把目标从背景里抠出来（目标=白，背景=黑）。
     (3) 铺路：findContours 只能处理单通道黑白图，它找的就是
         “黑底上的白色连通区域”。不二值化就没法找轮廓。
     (4) 减少计算量、抗一点光照干扰：处理 0/255 比 256 级灰度快，
         合适阈值还能抹平阴影、反光的灰阶差异。

  3. 关键：阈值
     - 阈值选得好不好直接决定成败：
         太低 -> 背景杂点也算目标（噪声多）
         太高 -> 目标一部分丢失（目标不完整）
     - 不同图片最佳阈值不同，所以考核要求“阈值可配置”（放进 Params）。

  4. 一句话
     二值化 = 用一条阈值线，把“灰度世界”砍成“黑白世界”，
     让计算机只关心“是不是目标”，方便下一步找轮廓。


  ---- 补充：Otsu、自适应阈值、类型对比 ----
  1. Otsu 自动阈值
        cv::threshold(grey, binary, 0, 255, cv::THRESH_BINARY | cv::THRESH_OTSU);
     thresh 写 0 即可，Otsu 自动找“类间方差最大”的阈值。
     适合直方图有明显双峰的图（深色目标 + 浅色背景）。
  2. 自适应阈值 adaptiveThreshold
        cv::adaptiveThreshold(grey, dst, 255,
            cv::ADAPTIVE_THRESH_MEAN_C, cv::THRESH_BINARY, 11, 2);
     每个像素用邻域均值/高斯加权算阈值，适合光照不均匀的图。
     blockSize 取奇数（邻域大小），C 是从均值里减掉的常数。
  3. 阈值类型对比
        THRESH_BINARY     : >thresh -> maxval，否则 0
        THRESH_BINARY_INV : 反过来（目标是暗色时用）
        THRESH_TRUNC      : >thresh 的截断为 thresh
        THRESH_TOZERO     : <=thresh 变 0
        THRESH_TOZERO_INV : >thresh 变 0
  4. 什么时候用 INV
     目标黑、背景白时，BINARY 会得到“背景白”，
     用 BINARY_INV 让目标变白，findContours 才找得到。
  5. 二值化前必须先灰度
     threshold 只接受单通道图。

八、任务3 题意：图像预处理流水线
  ---------------------------------------------------------------------------
  任务3 的 5 条要求不是孤立的，而是一条流水线，目的是把原图变成
  “能用于识别”的干净形状信息：

     原图
      ├─① BGR/灰度/HSV 转换 -> 换“视角”（不同色彩空间方便不同任务）
      ├─② 二值化 + 阈值      -> 砍成黑白，分离目标
      ├─③ 形态学去噪        -> 擦掉小白点、补上小洞
      ├─④ 轮廓查找          -> 找出目标的“边界”
      └─⑤ 画中心/坐标轴/框  -> 标注结果，建立坐标系

  逐条为什么需要：
  ① 色彩空间转换
     灰度：大多数几何处理（二值化、轮廓）只要亮度信息，最省事。
     HSV ：颜色识别（任务4）在 HSV 里阈值更好定，H 对光照不敏感。
  ② 二值化 + 阈值
     把目标从背景里分出来（见第七节）。
  ③ 形态学去噪
     二值化后边缘有毛刺、画面有小白点。开运算（先腐蚀后膨胀）
     擦掉小白点、保留大目标，让后面的轮廓更干净。
  ④ 轮廓查找
     findContours 在黑白图上找白色连通区域，每个区域给一圈边界点；
     用 contourArea 过滤太小的（噪声），留下真正的目标。
     轮廓是后续形状识别（任务5）的基础。
  ⑤ 画中心、坐标轴、检测框
     检测框(boundingRect)：标出目标在画面里的位置。
     中心点：目标中心，常是要输出的“结果”。
     坐标轴：明确坐标系方向（OpenCV 里 x 向右、y 向下，原点在左上角）。
     考核反复强调“坐标系定义”，画出来才能讲清目标在哪个方向。

  一句话：
     任务3 = 搭好整条“图像处理流水线”：
     换色彩空间 -> 二值化分离目标 -> 去噪 -> 找轮廓 -> 标注坐标系和位置。
     它是后面颜色/形状/数字识别（任务4/5/6）的共同前置步骤。

  为什么考试在意“坐标系”：
     最终要控制电机让箭头对准靶板（任务11）。视觉要输出目标位置和角度，
     坐标系方向搞错（比如 x 当 y），算出的角度就全错，电机转错方向。
     所以“画中心/坐标轴”看着简单，其实是后面所有定位计算的根基。


  ---- 补充：这条流水线在后续任务里怎么复用 ----
  1. 每一步产出什么
     mask    -> 给 findContours
     targets -> 给形状识别（顶点数/圆形度）
     center  -> 给对准与角度计算
  2. 各任务只换中间一步
     任务3：mask -> 轮廓 -> 画框
     任务4：HSV 阈值 -> mask -> 轮廓 -> 重心
     任务5：mask -> 轮廓 -> 几何特征 -> 形状标签
     任务6：mask -> 子轮廓(孔洞) -> OCR -> 数字
  3. 边界情况
     没有轮廓     -> 输出 valid=0，不要保留上一帧坐标
     多个目标     -> 遍历所有轮廓，或按面积取最大
     参数不合适   -> mask 全黑/全白，轮廓为 0 个或 1 个超大轮廓

九、makeMask 逐行详解（二值化 + 形态学去噪）
  添加时间：2026-10-16 21:30:59
  ---------------------------------------------------------------------------
  函数：
      cv::Mat makeMask(const cv::Mat& img, const Params& p){
          cv::Mat grey, binary;
          cv::cvtColor(img, grey, cv::COLOR_BGR2GRAY);
          cv::threshold(grey, binary, p.thresh, 255, cv::THRESH_BINARY);
          cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT,
                                                     cv::Size(p.morphSize, p.morphSize));
          cv::morphologyEx(binary, binary, cv::MORPH_OPEN, kernel);
          return binary;
      }

  1. 函数签名
     cv::Mat makeMask(const cv::Mat& img, const Params& p)
       - 返回 cv::Mat：返回处理好的二值掩膜（外面拿去显示/保存/找轮廓）。
       - const cv::Mat& img：输入图像，引用传递（不复制像素），const 表示不改它。
       - const Params& p：预处理参数（阈值、核大小），同样引用 + const。

  2. cv::Mat grey, binary;
     声明两个（空的）Mat：grey 放灰度图，binary 放二值图。

  3. cv::cvtColor(img, grey, cv::COLOR_BGR2GRAY);
     BGR 彩色图 -> 灰度图。二值化只需要亮度，所以先转灰度。

  4. cv::threshold(grey, binary, p.thresh, 255, cv::THRESH_BINARY);
     threshold 五个参数（顺序固定）：
         threshold(src, dst, thresh, maxval, type)
           src    : 输入，必须是单通道灰度图。
           dst    : 输出，二值图。
           thresh : 阈值（这里用 p.thresh，可配置）。
           maxval : 满足条件时赋的值（这里 255 = 白）。
           type   : 二值化方式。
     THRESH_BINARY 规则：
           像素 >  thresh  ->  maxval(255) 白
           像素 <= thresh  ->  0          黑
     常见 type：
       THRESH_BINARY     : >thresh -> maxval，否则 0（最常用）
       THRESH_BINARY_INV : 反过来，>thresh -> 0，否则 maxval（黑白互换）
       THRESH_TRUNC      : >thresh 的截断成 thresh
       THRESH_TOZERO     : <=thresh 的变 0
       THRESH_OTSU       : 自动计算阈值（用 | 与上面组合，如 THRESH_BINARY|THRESH_OTSU）

  5. cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT,
                                                cv::Size(p.morphSize, p.morphSize));
     构造“结构元素”（形态学核 kernel）：一个小形状模板，决定怎么腐蚀/膨胀。
         getStructuringElement(shape, ksize)
           shape : 核形状
                     MORPH_RECT    矩形（最常用）
                     MORPH_CROSS   十字形
                     MORPH_ELLIPSE 椭圆形
           ksize : 核大小 cv::Size(w, h)，这里宽高都等于 p.morphSize（5x5）。
     核越大，去噪越猛，但目标也会被削得更多。

  6. cv::morphologyEx(binary, binary, cv::MORPH_OPEN, kernel);
     形态学操作：
         morphologyEx(src, dst, op, kernel)
           op = MORPH_OPEN（开运算）= 先腐蚀后膨胀。
     四个基础概念：
       腐蚀 erode : 白色区域“缩小”，去掉小白噪点、断开细连接。
       膨胀 dilate: 白色区域“扩大”，填补小洞、连上断开处。
       开运算 open : 先腐蚀后膨胀。去小白点/毛刺，大目标基本保留。
       闭运算 close: 先膨胀后腐蚀。填补目标内部的小黑洞。
     src 和 dst 都写 binary：原地处理（结果覆盖输入）。
     kernel 决定操作力度。

  7. return binary;
     返回处理好的二值掩膜（单通道黑白图），外面可用于 findContours。

  8. 一句话
     makeMask = 灰度化 -> 阈值二值化 -> 开运算去噪 -> 返回黑白掩膜。


  ---- 补充：threshold 与 kernel 的细节 ----
  1. 为什么先 cvtColor 再 threshold
     threshold 只接受单通道；直接传三通道会抛异常。
  2. 固定阈值 vs Otsu
     固定阈值：光照稳定、对比固定时好用，可手动调。
     Otsu：自动，适合亮度会变但对比明显的场景。
  3. kernel 形状
     MORPH_RECT    矩形（默认，去方形噪声好）
     MORPH_ELLIPSE 椭圆（边缘更圆滑）
     MORPH_CROSS   十字（保留细线）
  4. kernel 大小
     3x3 轻微，5x5 常用，7x7 以上很猛（小目标会消失），一般取奇数。
  5. 返回值的开销
     return binary; 只复制“头”（引用计数），像素不复制，非常轻。

十、findTargets 逐行详解（轮廓查找 + 过滤）
  添加时间：2026-10-16 21:57:39
  ---------------------------------------------------------------------------
  函数：
      std::vector<std::vector<cv::Point>> findTargets(const cv::Mat& mask, const Params& p) {
          std::vector<std::vector<cv::Point>> contours;
          cv::findContours(mask.clone(), contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

          std::vector<std::vector<cv::Point>> kept;
          for (const auto& c : contours) {
              if (cv::contourArea(c) >= p.minArea) kept.push_back(c);
          }
          return kept;
      }

  1. 函数签名
     std::vector<std::vector<cv::Point>> findTargets(const cv::Mat& mask, const Params& p)
       - 返回“轮廓列表”，类型是二维嵌套的：
           外层 vector        -> 多条轮廓
           内层 vector<Point> -> 一条轮廓上的一串点
       - const cv::Mat& mask ：输入，黑白掩膜。
       - const Params& p    ：参数（用里面的 minArea）。

  2. std::vector<std::vector<cv::Point>> contours;
     声明一个空的轮廓列表，等下装 findContours 的结果。

  3. cv::findContours(mask.clone(), contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
     4 参数版本（不带 hierarchy）：
         findContours( image, contours, mode, method )
           image   : 输入图，必须 8 位单通道黑白图，且“黑底白目标”。
                     用 mask.clone()，因为 findContours 可能改动输入，传副本稳妥。
           contours: 输出，装找到的轮廓。
           mode    : 轮廓检索模式。
           method  : 轮廓点压缩方式。

     检索模式 mode（RETR_*）：
       RETR_EXTERNAL : 只找最外层轮廓（最常用，忽略内部嵌套）。
       RETR_LIST     : 找所有轮廓，不建立父子关系。
       RETR_CCOMP    : 两层结构（外轮廓 + 内孔）。
       RETR_TREE     : 完整树状层级（父子孙都有）。

     点压缩方式 method（CHAIN_APPROX_*）：
       CHAIN_APPROX_NONE   : 存轮廓上所有点（最全但最占内存）。
       CHAIN_APPROX_SIMPLE : 只存拐点，直线段中间的点省略（最常用）。

  4. std::vector<std::vector<cv::Point>> kept;
     装“过滤后”要保留的轮廓。

  5. 过滤循环
         for (const auto& c : contours) {
             if (cv::contourArea(c) >= p.minArea) kept.push_back(c);
         }
       - for (const auto& c : contours)：遍历每条轮廓。
           const auto& = 引用遍历（不复制点），const 表示不改它。
       - cv::contourArea(c)：算这条轮廓的面积。
       - >= p.minArea：面积够大才保留（过滤太小的噪声轮廓），
           这里用上了 Params 的第 3 个成员 minArea。
       - kept.push_back(c)：存进结果。

  6. return kept;
     返回过滤后的目标轮廓列表。

  7. 一句话
     findTargets = 在黑底白目标的掩膜上找最外层轮廓，
     再用面积过滤掉小噪声，返回真正的目标轮廓。


  ---- 补充：轮廓的其它几何量 ----
  1. contourArea 与 boundingRect 面积不同
     contourArea   ：轮廓围成的实际面积
     boundingRect  ：外接矩形面积 = w * h
     倾斜的目标两者差很多。
  2. 轮廓点顺序
     点沿边界按顺序排列，但起点和方向（顺/逆时针）不保证。
  3. approxPolyDP 多边形逼近
        cv::approxPolyDP(contour, approx, epsilon, true);
     epsilon 越大顶点越少；常用 epsilon = 0.02 * arcLength。
     用来数顶点判断三角形/四边形（任务5）。
  4. 凸包与凹陷
        cv::convexHull(contour, hull);
        cv::convexityDefects(contour, hullIdx, defects);
     凸包=把轮廓“绷紧”的多边形；凹陷可识别星形、箭头。
  5. 为什么传 clone()
     findContours 某些版本会改写输入图，不想破坏原掩膜就传副本。
  6. 面积过滤经验值
     <100 多为噪点；占画面 1% 以上通常是真目标。

十一、drawOverlay 逐行详解（画中心/坐标轴/检测框）

  函数：
      void drawOverlay(cv::Mat& img, const std::vector<std::vector<cv::Point>>& targets) {
          cv::Point center(img.cols / 2, img.rows / 2);
          cv::circle(img, center, 5, cv::Scalar(0, 0, 255), -1);
          cv::arrowedLine(img, center, cv::Point(center.x + 60, center.y),

          for (const auto& c : targets) {

          }
      }

  1. 函数签名（关键点）
     void drawOverlay(cv::Mat& img, const std::vector<std::vector<cv::Point>>& targets)
       - cv::Mat& img ：注意不是 const！绘制函数会直接改动这张图（画上去），
                        必须用非 const 引用，改动才反映到外面。
                        正因为会改图，processImage 里先 img.clone() 再画，不破坏原图。
       - const ...& targets ：轮廓列表，只读，所以 const。

  2. cv::Point center(img.cols / 2, img.rows / 2);
     取图像中心。cols=宽，rows=高，所以 center.x=宽/2，center.y=高/2。

  3. cv::circle(img, center, 5, cv::Scalar(0, 0, 255), -1);
     画图像中心点：circle(img, 圆心, 半径, 颜色, 粗细)
       圆心 center，半径 5，颜色 Scalar(0,0,255)=红色(BGR)。
       粗细 -1 = 填充(实心圆)；正数 = 只画轮廓线，数字是线宽。

  4. cv::arrowedLine(img, center, cv::Point(center.x + 60, center.y),
                     cv::Scalar(0, 0, 255), 2);
     画 x 轴：arrowedLine(img, 起点, 终点, 颜色, 粗细)
       起点=中心，终点=中心向右 60 像素 -> x 正方向向右。红色。

  5. cv::arrowedLine(img, center, cv::Point(center.x, center.y + 60),
                     cv::Scalar(0, 255, 0), 2);
     画 y 轴：终点=中心向下 60 像素 -> y 正方向向下。绿色。
     ! 坐标系关键：OpenCV 原点在左上角，x 向右，y 向下。
       所以 +x 向右、+y 向下——这就是考核强调的“坐标系定义”。

  6. 画检测框
         for (const auto& c : targets) {
             cv::rectangle(img, cv::boundingRect(c), cv::Scalar(0, 255, 0), 2);
         }
       遍历每个目标轮廓 c：
         cv::boundingRect(c) -> 求轮廓的轴对齐外接矩形(Rect，含 x,y,w,h)。
         cv::rectangle(img, 矩形, 颜色, 粗细) -> 画检测框，绿色，线宽 2。
       参数也给两个对角 Point 的另一种写法。

  7. 三个绘图函数参数速记
       circle(img, center, radius, color, thickness)   圆心、半径、颜色、粗细(-1=实心)
       arrowedLine(img, pt1, pt2, color, thickness)    起点、终点、颜色、粗细
       rectangle(img, rect, color, thickness)          矩形、颜色、粗细
     共同点：都直接修改 img（参数不能 const），颜色用 Scalar(BGR)，
             粗细整数（-1=填充）。

  8. 一句话
     drawOverlay = 在图上画中心点、坐标轴(x右y下)、以及每个目标的检测框，
     直接改图，所以调用前要 clone。

        cv::line(img, p1, p2, color, thickness);

十二、颜色识别相关函数详解（Point2f/inRange/bitwise_or/moments/putText）
  添加时间：2026-10-17 22:56:22
  ---------------------------------------------------------------------------
  1. cv::Point2f —— 浮点坐标点
     cv::Point2f center = {0, 0};
       - 二维点，但坐标是 float（不是 int）。
       - 成员：center.x、center.y。
       - 对比：cv::Point 坐标是 int（整数像素）；
               cv::Point2f 坐标是 float（可带小数，亚像素精度）。
       - 为什么用 f：重心算出来常是 320.47 这种小数，用 int 会丢精度。

  2. getColorRange —— 颜色名 -> HSV 范围（自定义函数）
     bool getColorRange(const std::string& name,
                        cv::Scalar& lo1, cv::Scalar& hi1,
                        cv::Scalar& lo2, cv::Scalar& hi2, bool& hasSecond);
       - 作用：输入颜色名(如 "red")，输出它的 HSV 上下界。
       - 为什么需要：考核要求“考官重新指定颜色后仍能识别”，
         所以颜色不能写死，用“颜色名 -> 范围”的表，换颜色只传不同字符串。
       - 为什么有 lo1/hi1 和 lo2/hi2 两套：
         红色跨色相环两端，H 在 0~10 和 170~179 都是红色，
         需要两个区间，之后用 bitwise_or 合并。hasSecond 标记“是否有第二段”。
       - 为什么 S/V 下界取 50：排除白色(S低)、黑色(V低)、太暗的像素。
       - 返回 bool：颜色名不认识时返回 false，程序好处理。

  3. cv::inRange —— 颜色分割（核心）
     cv::inRange(hsv, lo1, hi1, mask);
       参数：inRange(输入图, 下界, 上界, 输出掩膜)
       规则（闭区间，逐通道判断）：
         每个像素每个通道： lower <= 值 <= upper -> 255(白)，否则 -> 0(黑)
         三个通道都满足才算目标（H、S、V 都在范围内）。
       要点：输入用 HSV 图，则 Scalar 是 (H, S, V)；
             输出 mask 是单通道黑白图(0/255)。

  4. cv::bitwise_or —— 按位或（合并掩膜）
     cv::bitwise_or(mask, mask2, mask);
       - 作用：两个掩膜逐像素做“或”，即“任一为白，结果就是白”。
       - 为什么用：红色有两段 H 区间，分别 inRange 得到两张掩膜，
         合并成一张：mask = (H 在 0~10) 或 (H 在 170~179)。
       - 参数：bitwise_or(图1, 图2, 输出图)。

  5. cv::morphologyEx —— 形态学操作
     cv::morphologyEx(mask, mask, cv::MORPH_OPEN,  kernel);  // 开：去小白点
     cv::morphologyEx(mask, mask, cv::MORPH_CLOSE, kernel);  // 闭：补小洞
       参数：morphologyEx(输入, 输出, 操作类型, 核)
       常用类型：
         MORPH_OPEN     : 先腐蚀后膨胀 -> 去小白点、毛刺
         MORPH_CLOSE    : 先膨胀后腐蚀 -> 填补目标内部小洞
         MORPH_GRADIENT : 膨胀 - 腐蚀   -> 得到轮廓边缘
         MORPH_TOPHAT   : 原图 - 开运算 -> 提取小亮点
         MORPH_BLACKHAT : 闭运算 - 原图 -> 提取小暗点
       先开后闭：先去噪再补洞，掩膜更干净。

  6. cv::moments / cv::Moments —— 求重心
     cv::Moments m = cv::moments(contours[best]);
     if (m.m00 != 0) {
         center = cv::Point2f(m.m10 / m.m00, m.m01 / m.m00);
     }
       - 是什么：图像/轮廓的“矩”(moments)，可算面积、重心、方向等。
       - 关键量：
           m.m00 : 面积（零阶矩）
           m.m10 : x 方向一阶矩
           m.m01 : y 方向一阶矩
       - 重心公式： cx = m10/m00,  cy = m01/m00
       - 为什么要判 m00 != 0：面积是 0 时不能做除数（会得到 inf/nan）。
       - 为什么用重心而不是外接框中心：重心是目标形状的“质量中心”，
         比矩形中心更准（对不规则形状尤其）。

  7. cv::putText —— 在图上写字
     cv::putText(img, "valid=1", cv::Point(10, 30),
                 cv::FONT_HERSHEY_SIMPLEX, 0.8, cv::Scalar(0, 255, 0), 2);
       参数（顺序）：
         1 img         : 要写的图
         2 "valid=1"   : 文本内容
         3 Point(10,30): 文本左下角的位置（默认是左下角，不是左上角）
         4 FONT_HERSHEY_SIMPLEX : 字体
         5 0.8         : 字体缩放（大小）
         6 Scalar(0,255,0) : 颜色（BGR，绿）
         7 2           : 线宽
       注意：org 是左下角，所以 y=30 时文字在顶部往下一点。

  8. 一句话
     颜色识别链路：Point2f 存中心 -> getColorRange 选范围 -> inRange 分割
     -> bitwise_or 合并红两段 -> morphologyEx 去噪 -> moments 求重心
     -> putText 标注结果。


  ---- 补充：识别里常用的其它函数 ----
  1. cv::minEnclosingCircle —— 最小外接圆
        cv::minEnclosingCircle(contour, center, radius);
     用填充率判圆（任务5）：
        fill = contourArea / (PI * radius * radius)
     圆≈1，正方形≈0.64，三角形≈0.4。
  2. cv::arcLength —— 轮廓周长
        double peri = cv::arcLength(contour, true);   // true = 闭合
  3. cv::approxPolyDP —— 多边形逼近
     见第十节补充，用来数顶点。
  4. cv::matchTemplate —— 模板匹配
        cv::matchTemplate(img, tmpl, res, cv::TM_CCOEFF_NORMED);
     在每个位置算相似度，res 的最大值就是最佳匹配，值域约 -1~1。
     注意：对尺度、旋转、字体非常敏感（任务6 模板匹配失败的原因）。
  5. cv::findNonZero —— 找出所有非零像素坐标
        std::vector<cv::Point> pts;
        cv::findNonZero(binary, pts);
     常用来求二值图内容的紧致外接框。
  6. Vec3b 与 Scalar
     Vec3b 是“像素容器”（3 个 uchar），配 at<Vec3b> 读写像素；
     Scalar 是“参数容器”（最多 4 个 double），用于传颜色/阈值。

十三、HSV 颜色空间详解（概念：为什么用 HSV）
  添加时间：2026-10-17 23:08:32
  （第二节只有颜色表，这里补概念）
  ---------------------------------------------------------------------------
  1. HSV 是什么
     另一种描述颜色的方式，三个分量：
       H  Hue        色相   : 是什么颜色（红/黄/绿/蓝…）
       S  Saturation 饱和度 : 颜色有多“纯”（鲜艳 <-> 灰白）
       V  Value      明度   : 有多亮（亮 <-> 黑）
     对比 BGR：BGR 是“三盏灯各开多亮”，人很难直观判断是什么颜色；
     HSV 是“什么颜色 + 多鲜艳 + 多亮”，符合人的直觉。

  2. 三个分量逐个理解
     H（色相）：想象一个色相环，从红开始转一圈：红->黄->绿->青->蓝->紫->粉->红。
        OpenCV 里 H 范围是 0~179（不是 0~360！）。
     S（饱和度）：S 高=颜色鲜艳纯；S 低=发灰发白。范围 0~255。
        白色、灰色 S 很低，所以把 S 下界设高(如 50)能排除白/灰。
     V（明度）：V 高=明亮；V 低=暗、接近黑。范围 0~255。
        黑色、暗处 V 很低，所以把 V 下界设高能排除黑/太暗区域。

  3. 为什么颜色识别用 HSV 而不用 BGR（最关键）
     BGR 的问题：颜色和亮度混在一起。同一块红布，亮处 (50,50,220)，
       暗处 (20,20,90)，光照一变 BGR 数值差很多，很难用固定范围框住。
     HSV 的优势：颜色(H) 和亮度(V) 分开了。同一块红布 H 几乎不变，
       光照变化主要影响 V，对 H 影响很小。
     一句话：HSV 把“颜色”和“亮度”解耦了，所以光照变化时仍能稳定识别颜色。
       这是颜色识别必须用 HSV 的根本原因。

  4. OpenCV 的 HSV 范围（重要）
       H : 0~179（常见教程是 0~360；OpenCV 为存进 8 位把 H 除以 2）
       S : 0~255
       V : 0~255
     ! 最大的坑：写 H 阈值不要超过 179。按 0~360 的表写会全错。
     换算：OpenCV_H = 角度 / 2。例：红 0°->H0，绿 120°->H60，蓝 240°->H120。

  5. 红色的特殊之处：跨色相环两端
     红色在色相环首尾相接：一端 H≈0~10，另一端 H≈170~179。
     所以要两个区间，分别 inRange 再 bitwise_or 合并：
         inRange(hsv, Scalar(0,50,50),   Scalar(10,255,255),  mask1);
         inRange(hsv, Scalar(170,50,50), Scalar(179,255,255), mask2);
         bitwise_or(mask1, mask2, mask);

  6. 实际例子（识别绿色）
         cv::Mat hsv;
         cv::cvtColor(bgr, hsv, cv::COLOR_BGR2HSV);
         cv::Scalar lower(35, 50, 50);      // H35, S50, V50
         cv::Scalar upper(85, 255, 255);    // H85, S/V 满
         cv::Mat mask;
         cv::inRange(hsv, lower, upper, mask);
     含义：H 35~85 是绿色色相范围；S 50~255 排除灰白；V 50~255 排除黑/太暗。

  7. 怎么调阈值（实操经验）
     目标没识别全   -> 放宽 H 范围（上下各扩几点）
     混入别的东西   -> 收紧 H 范围
     混入白色/灰色  -> 提高 S 下界（如 50->100）
     混入黑色/阴影  -> 提高 V 下界
     亮处/暗处不稳  -> 主要看 H（更稳），适当放宽 V

  8. 一句话
     HSV = 色相(什么颜色) + 饱和度(纯不纯) + 明度(亮不亮)。
     它把颜色和亮度解耦，所以光照变化时颜色依然稳定，是颜色识别首选。
     OpenCV 里 H 是 0~179（不是 0~360），红色要两段合并。


  ---- 补充：其它颜色空间与光照极限 ----
  1. HLS
     H 色相、L 亮度、S 饱和度；和 HSV 类似，只是“亮度”的定义不同。
  2. Lab
     L 亮度、a 绿-红、b 蓝-黄；更接近人眼感知，常用于色差比较。
  3. 为什么颜色识别首选 HSV
     H 独立于亮度，阈值直观，OpenCV 支持完善。
  4. 光照的极限
     过曝（全白）和欠曝（全黑）时 S/V 已无信息，H 也不可靠，
     任何颜色识别都会失败，只能靠控制曝光。

十四、为什么先开运算再闭运算
  添加时间：2026-10-17 23:46:28
  （第九节只讲了开/闭定义，这里讲顺序原因）
  ---------------------------------------------------------------------------
  1. 先复习两个操作
     开运算 OPEN  : 先腐蚀后膨胀。白色先缩小再长回。作用：去小白点、毛刺、细连接。
     闭运算 CLOSE : 先膨胀后腐蚀。白色先扩大再缩回。作用：补小白洞、连接断开处。
     腐蚀=白色缩小；膨胀=白色扩大。开/闭都是“变了再变回来”，
     整体大小基本不变，只动小结构。

  2. 为什么先开运算（核心）
     二值化后常见噪声是零散的小白点（背景杂色）；
     目标内部常见的是小黑洞（反光、暗点）。
     先开：把小白点清掉。后闭：把小黑洞补上。
     顺序刚好对应“先除噪，再补洞”。

  3. 如果反过来（先闭后开）会怎样
     例子：白色方块中间一个黑洞，旁边一个孤立小白噪声点。
     先闭（先膨胀）：白方块扩大，孤立白噪声也扩大；
       若噪声靠近目标，膨胀时可能直接连到目标上，变成目标一部分。
     再腐蚀缩回：连上去的那块不一定能分离，目标边上留个凸起。
     再开运算也难把这个已经粘住的凸起干净去掉 -> 噪声污染目标形状。
     先开（先腐蚀）：孤立小白点直接被腐蚀掉（消失）；
       再膨胀长回，目标恢复；然后闭运算只负责把目标黑洞补上。
       -> 噪声没了，洞也补了，目标干净。

  4. 一句话
     开运算负责“去掉不该有的白”，闭运算负责“补上不该有的黑”。
     必须先去噪(开)再补洞(闭)——否则先膨胀会把噪声放大、甚至粘到目标上，
     再也清不干净。

  5. 实际颜色识别里的表现
     二值化出来的掩膜常有：边缘毛刺/零散小白点（开运算清掉）；
     目标内部因反光/阴影形成的黑洞（闭运算补上）。
     不补洞会导致 findContours 找到的轮廓面积偏小，
     甚至洞太大时目标被拆成几块。所以先开后闭让中心计算/轮廓判断更稳。

  6. 什么时候只用一种
     只有小白点噪声 -> 只开运算
     只有黑洞       -> 只闭运算
     两者都有(最常见) -> 先开后闭（当前做法）

  7. 核大小决定力度
     cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT, cv::Size(5, 5));
     核越大(7x7、9x9)，去噪/补洞越猛，但目标也会被削得更多。5x5 是常用起点。


  ---- 补充：形态学的进阶参数 ----
  1. iterations 迭代次数
        cv::morphologyEx(src, dst, op, kernel, cv::Point(-1,-1), 2);
     迭代 2 次 = 做两遍，效果更强（相当于核变大）。
  2. anchor 锚点
     默认 (-1,-1) 表示核的中心。
  3. borderType 边界处理
     默认 BORDER_CONSTANT；边缘处理时可用 BORDER_REPLICATE 复制边缘像素。
  4. 与 erode/dilate 的关系
     erode、dilate 是单步操作；morphologyEx 是组合操作。
        erode + dilate  == MORPH_OPEN
        dilate + erode  == MORPH_CLOSE
  5. 形态学梯度
     MORPH_GRADIENT = 膨胀 - 腐蚀 -> 得到目标边缘，
     可当作粗边缘检测（比 Canny 简单，但更粗）。

十五、数字识别新增内容（hierarchy / 缩放 / Tesseract）
  添加时间：2026-10-18 11:15:24
  （只记之前没讲过的；hierarchy 类型见三.14，RETR_TREE 名字见第十节）
  ---------------------------------------------------------------------------
  1. hierarchy 怎么用（新）
     cv::Vec4i 是 4 个 int，含义固定：
         hier[i] = [ next, previous, firstChild, parent ]
                     [0]     [1]        [2]       [3]
       hier[i][3] = 父轮廓下标，-1 表示没有父（顶层）。
     在“形状内部有数字”的图里：形状是顶层(parent=-1)，数字是形状内部的孔洞(子轮廓)。
     挑数字的判据：
         int parent = hier[i][3];
         if (parent >= 0 && hier[parent][3] == -1) idx.push_back(i);
       意思：我有父轮廓，且我爹是顶层 -> 我是形状里面的孔洞 -> 是数字。

  2. cv::copyMakeBorder（新）
     cv::copyMakeBorder(big, pad, 20, 20, 20, 20, cv::BORDER_CONSTANT, cv::Scalar(255));
       - 作用：给图像四周加边框。
       - 参数：(输入, 输出, 上, 下, 左, 右, 边框类型, 颜色)。
       - 这里加 20 像素白边，因为 Tesseract 贴着边缘的文字识别率差。

  3. cv::resize（新）
     double scale = 100.0 / roi.rows;
     cv::resize(roi, big, cv::Size(), scale, scale, cv::INTER_LINEAR);
       - 作用：缩放图像。
       - dsize 传 cv::Size()（空），改用 fx/fy 缩放倍数。
       - INTER_LINEAR：双线性插值，放大后边缘平滑。
       - 为什么要放大：Tesseract 对字高 30~100 像素最敏感，小字识别率低。

  4. cv::format（新）
     std::string text = cv::format("%d (%.0f)", label, conf);
       - 和 printf 一样用格式串，但返回 std::string。
       - 比 snprintf + char[] 简洁，不用管缓冲区大小。

  5. Tesseract 调用流程（全新增）
     tesseract::TessBaseAPI api;                           // 1 创建 OCR 引擎对象
     api.Init(NULL, "eng");                                // 2 初始化，用英文模型；NULL=默认 tessdata 路径
     api.SetPageSegMode(tesseract::PSM_SINGLE_CHAR);       // 3 告诉它“这里只有一个字符”
     api.SetVariable("tessedit_char_whitelist", "0123456789");  // 4 只允许识别 0-9
     api.SetImage(pad.data, pad.cols, pad.rows, 1, static_cast<int>(pad.step)); // 5 送入图像
     char* txt = api.GetUTF8Text();                        // 6 识别，返回文本
     int conf = api.MeanTextConf();                        // 7 平均置信度 0~100
     api.Clear();                                          // 8 清掉上一次的识别状态
     delete[] txt;                                         // 9 释放返回的 C 字符串
     关键点：
       Init(NULL,"eng")     : 第一个参数是 tessdata 目录，NULL 用系统默认。
       PSM_SINGLE_CHAR      : 页面分割模式，当成单个字符。
       whitelist            : 白名单，限定只输出 0-9，避免识别成字母。
       SetImage 5 个参数    : (数据指针, 宽, 高, 通道数, 每行字节数)。
       MeanTextConf()       : 返回 0~100，不是 0~1。
       Clear()              : 每次识别后调用，否则状态累积。

  6. 可选依赖（新）
     CMake：
         find_package(PkgConfig QUIET)
         if (PkgConfig_FOUND)
             pkg_check_modules(TESSERACT QUIET tesseract)
         endif()
         if (TESSERACT_FOUND)
             target_link_libraries(task6 ${TESSERACT_LIBRARIES})
             target_compile_definitions(task6 PRIVATE HAVE_TESSERACT)
         endif()
     代码：
         #ifdef HAVE_TESSERACT
         #include <tesseract/baseapi.h>
         #endif
     效果：别的机器没装 Tesseract 也照样编译通过，只是 label=-1（识别失败），不崩。

  7. 置信度
     MeanTextConf() 返回 0~100 的整数。这里 confMin=50.0，低于 50 判为识别失败。
     实测该图 96~97。注意它和模板匹配的 0~1 不同，别混用阈值。

  8. 一句话
     数字识别链路：Otsu 二值化 -> 用 hierarchy 取“形状内部的孔洞”当数字区域
     -> 放大 + 加白边 -> Tesseract(单字符+白名单) -> 输出 label/center/confidence。


  ---- 补充：数字识别的其它细节 ----
  1. findNonZero + boundingRect 求紧致框
        std::vector<cv::Point> pts;
        cv::findNonZero(bin, pts);
        cv::Rect box = cv::boundingRect(pts);
     得到“内容的最小外接矩形”，用来裁出数字。
  2. 归一化为什么重要
     不同位置/大小的数字直接比对必然失败；
     先裁到内容、再等比缩放到固定画布、居中，才能比较。
  3. 模板匹配为什么失败
     模板用 FONT_HERSHEY_SIMPLEX 生成，而实际贴纸是圆润字体，
     笔画粗细与形状差异大，3 被认成 6/8/9。
     模板匹配对字体、尺度、粗细极敏感。
  4. Tesseract 为什么更好
     内部是训练好的模型，对字体差异和轻微变形更鲁棒，还能给置信度。
  5. PSM 页面分割模式
     PSM_SINGLE_CHAR  单个字符
     PSM_SINGLE_LINE  一行
     PSM_SINGLE_WORD  一个词
     PSM_AUTO         自动（默认）
  6. tessdata 路径
     Init 第一个参数为 NULL 时用系统默认
     （Linux 常见 /usr/share/tesseract-ocr/5/tessdata）。
     换机器或换语言包时可显式传路径。
  7. 多个数字
     一次 SetImage 只识别一个区域；多个目标要循环，每个 ROI 各识别一次。
  8. 灰度 vs 二值送 OCR
     二值图（黑字白底）通常比灰度更稳；但噪声多时灰度反而更好，
     可以两种都试。

十六、统一输入结构涉及的知识点（新）
  添加时间：2026-10-21 01:50:04
  ---------------------------------------------------------------------------
  1. 判断“参数是不是纯数字”
     if (!path.empty() && path.find_first_not_of("0123456789") == std::string::npos)
       - find_first_not_of("0123456789")：从左往右找第一个“不是数字”的字符，返回下标。
       - 找不到 -> 返回 std::string::npos（特殊常量，表示“没找到”）。
       - 所以“找不到非数字字符” = 全是数字 = 纯数字参数。
       - !path.empty() 防止空字符串（空串也会返回 npos）。

  2. std::stoi / std::stod —— 字符串转数字
     int    idx     = std::stoi(argv[1]);   // "0"     -> 0
     double minArea = std::stod(argv[2]);   // "300.0" -> 300.0
       - stoi = string to int；stod = string to double。
       - argv 里永远是字符串，要当数字用必须先转换。
       - 注意：字符串不是数字（如 "abc"）会抛异常，程序崩溃。

  3. cv::VideoCapture 的两种打开方式（关键）
     cv::VideoCapture cap(0);              // 整数 0 -> 摄像头（设备索引）
     cv::VideoCapture cap("video.mp4");    // 字符串 -> 文件路径
       - 参数是整数：摄像头索引（0 = 默认摄像头）。
       - 参数是字符串：文件路径。
       - 所以 cap("0")（字符串）会去找名叫 0 的文件，打不开。

  4. auto —— 让编译器推断类型
     auto cap = common::openVideo(path);   // cap 的类型是 cv::VideoCapture
       - 长类型名不用手写。
       - 必须在定义时就有初值。

  5. 为什么用 cv::VideoCapture& 传参
     void processStream(cv::VideoCapture& cap, ...)
       - & = 引用传递，函数里操作的就是外面那个对象（不是副本）。
       - VideoCapture 管着底层设备/文件句柄，不能随便复制。
       - 不能传临时对象：processStream(common::openVideo(path), ...) 编译错误，
         因为非 const 引用不能绑定临时值。
       - 所以要分两步：
           auto cap = common::openVideo(path);
           processStream(cap, ...);

  6. static 局部变量 —— 只初始化一次
     static tesseract::TessBaseAPI api;
     static bool inited = false;
     if (!inited) { api.Init(NULL, "eng"); ...; inited = true; }
       - 函数里的 static 变量只在第一次进入时初始化，之后一直存在（生命周期到程序结束）。
       - 用途：Tesseract 加载模型很慢，只 Init 一次，视频每帧复用。
       - 不加 static 就每帧新建/初始化，视频会极慢。

  7. std::filesystem::path::extension() —— 取扩展名
     std::string ext = std::filesystem::path("a/b/video.mp4").extension().string();  // ".mp4"
       - 返回带点的扩展名；没有扩展名返回空串。
       - 用来判断输入是图片还是视频。

  8. waitKey 返回值和 ESC
     if (cv::waitKey(30) == 27) break;
       - waitKey(30) 返回按键的 ASCII 码，没按键返回 -1。
       - 27 是 ESC 键的 ASCII 码。

  9. 为什么摄像头分支要放在 exists 检查前面
     if (纯数字) { 打开摄像头; return; }      // 先判断
     if (!std::filesystem::exists(path)) { ... }
       - "0" 不是文件，exists("0") 返回 false，会直接报“路径不存在”。
       - 所以必须先判断“是不是摄像头索引”，处理完直接 return。

  10. 一句话
     输入分流顺序：纯数字 -> 摄像头；视频扩展名 -> 视频；否则 -> 图片。
     视频和摄像头共用 processStream(cv::VideoCapture&, ...)，因为都是逐帧读。


  ---- 补充：命令行参数与异常处理 ----
  1. argc / argv
     argc = 参数个数（含程序名本身）
     argv[0] = 程序路径；argv[1] 起是用户参数，类型都是 char*
  2. std::stoi 的异常
     参数不是数字会抛 std::invalid_argument，超出范围抛 std::out_of_range。
     稳妥写法：
         try { p.thresh = std::stoi(argv[2]); }
         catch (...) { std::cerr << "bad number" << std::endl; return 1; }
  3. 引用与指针
     引用 &：必须绑定已有对象、不能为空，用法像普通变量。
     指针 *：可以为空，需要判空再解引用。
     函数参数优先用引用；需要“可选”时用指针或 std::optional。
  4. 为什么 processStream 不返回值
     它直接写视频/显示，结果通过文件输出；
     若需要返回统计信息，可改成返回结构体或加引用参数。
  5. 分流顺序的健壮性
     先判空串 -> 再判纯数字 -> 再判文件存在 -> 最后看扩展名。
     顺序错了就会出现“把 0 当文件名”的错误。

颜色识别学习代码（参考）
添加时间：2026-09-15 23:24:34
作用：演示使用 HSV 颜色空间识别绿色物体的大致流程，包括：
  1. 读取图片并转换为 HSV；
  2. 使用 inRange 提取绿色区域；
  3. 使用形态学操作去除噪声；
  4. 使用 findContours 查找连通区域；
  5. 使用 contourArea 和 boundingRect 判断目标大小和位置；
  6. 在原图上绘制矩形和文字。

#include <opencv2/opencv.hpp>
#include <vector>

int main() {
    cv::Mat src = cv::imread("D:/opencecpp/2025test1.png");

    // 1. BGR 转 HSV
    cv::Mat hsv;
    cv::cvtColor(src, hsv, cv::COLOR_BGR2HSV);

    // 2. 绿色大致范围
    cv::Scalar lower(35, 50, 50);
    cv::Scalar upper(85, 255, 255);

    cv::Mat mask;
    cv::inRange(hsv, lower, upper, mask);

    // 3. 可选：去噪
    cv::Mat kernel = cv::getStructuringElement(cv::MORPH_RECT, cv::Size(5, 5));
    cv::erode(mask, mask, kernel);
    cv::dilate(mask, mask, kernel);

    // 4. 找连通区域
    std::vector<std::vector<cv::Point>> contours;
    std::vector<cv::Vec4i> hierarchy;
    cv::findContours(mask, contours, hierarchy,
                     cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);

    // 5. 逐个判断并画框
    for (size_t i = 0; i < contours.size(); ++i) {
        double area = cv::contourArea(contours[i]);
        if (area < 500) continue;

        cv::Rect rect = cv::boundingRect(contours[i]);
        cv::rectangle(src, rect, cv::Scalar(0, 255, 0), 2);
        cv::putText(src, "green", cv::Point(rect.x, rect.y - 5),
                    cv::FONT_HERSHEY_SIMPLEX, 0.6,
                    cv::Scalar(0, 255, 0), 2);
    }

    cv::imshow("result", src);
    cv::waitKey(0);
    return 0;
}
